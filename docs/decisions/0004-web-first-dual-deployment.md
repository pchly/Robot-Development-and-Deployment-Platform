# ADR-0004：Web优先并支持中央与端侧双部署

- 状态：已接受
- 日期：2026-10-02

## 背景

机器人开发既有实验室内从Windows工作站管理Jetson的场景，也有工程师携带笔记本到机器人旁、在无互联网环境中调试单台设备的场景。硬件SDK、GPU推理和工作流必须在端侧运行，但这不意味着操作界面必须成为直接访问硬件的桌面客户端。

## 决策

采用“Web优先、端侧常驻、控制面可移动”的部署方式：

- Web Studio是唯一主要操作界面；
- Edge Agent、Edge Executor和工作流Runtime始终运行在机器人端侧；
- Platform API和Web Studio支持两种部署模式，但使用同一套代码和协议；
- 浏览器不直接访问USB、CAN、串口、Docker Socket或厂商SDK；
- 已启动的端侧工作流不依赖浏览器存活，也不依赖控制面持续联网；
- 如未来确有桌面集成需求，可用PWA或轻量桌面壳封装同一套Web Studio，不另建一套硬件访问逻辑。

## 部署模式

| 模式 | Web Studio与Platform API | Edge组件 | 使用场景 |
| --- | --- | --- | --- |
| 开发模式 | Windows开发机 | Jetson | 当前研发、调试和快速迭代 |
| 单机现场模式 | Jetson本机轻量部署，笔记本通过浏览器访问 | 同一台Jetson | 无互联网、单机器人交付和维护 |
| 集群模式 | 局域网服务器或中央服务 | 每台机器人各自运行 | 多机器人、团队协作和集中运维 |

单机现场模式下，工程师连接机器人局域网并打开端侧地址。浏览器关闭或笔记本离开后，Jetson上的已授权工作流继续运行。

## 开发与运行的区别

- 源代码可以在Windows或团队代码仓库中开发；
- 通用逻辑由自动化测试和多架构构建验证；
- 硬件相关代码必须在Jetson和真实硬件上完成硬件在环验收；
- 发布时部署的是固定版本和摘要的端侧制品，不是在生产Jetson上临时修改源代码；
- TensorRT等目标相关制品可以在目标Jetson受控生成并缓存。

“代码在端侧运行”不等于“所有代码必须在端侧编写”。

## 结果

正面影响：

- 一套界面覆盖开发、现场和集群场景；
- 不需要维护Windows、Linux和Jetson三套原生GUI；
- 硬件权限不进入浏览器进程；
- 可以离线运行并逐步扩展到多机器人。

代价：

- Platform API必须支持单机和中央两种拓扑；
- 节点身份、TLS、认证和审计在远程模式启用前必须完成；
- 需要明确控制面失联时的端侧期望状态和恢复规则。
