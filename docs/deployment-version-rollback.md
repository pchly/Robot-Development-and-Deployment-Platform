# Deployment版本快照与安全回退

每个`DeploymentPlan`都是一次不可变运行快照，固定以下内容：

- 项目与工作流修订来源；
- 节点参数与画布连接；
- 组件引用和组件版本；
- Runtime、插件与TensorRT Engine等端侧制品契约；
- 目标Edge节点与创建时间。

回退不会修改历史记录，也不会简单重新读取当前Catalog。平台复制所选历史计划的完整快照，生成新的`plan_id`，并记录`rollback_of_plan_id`和`supersedes_plan_ids`，因此回退本身也是一条可审计的新部署。

## 安全切换状态机

1. 用户在已停止或失败的历史记录上选择“回退到此版本”；
2. 若没有硬件冲突，新计划直接进入`pending`；
3. 若当前Runtime占用相同硬件，平台先下发停止并让新计划保持`queued`；
4. `queued`计划不会出现在Agent的活动计划列表中；
5. 只有全部被替换计划回报`stopped`后，回退计划才自动进入`pending`；
6. 任一停止操作回报`failed`时，回退计划继续排队且不会启动；
7. 用户可以取消尚未启动的排队回退。

部署记录与排队关系保存在SQLite中，Platform API重启后仍能恢复并继续状态转换。重复点击同一历史版本会返回同一条活动回退记录，不会重复创建并发计划。
