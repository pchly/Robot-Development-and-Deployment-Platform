# 问题定义与第一阶段验收标准

## 问题定义

机器人项目通常需要重复完成硬件选型、驱动适配、算法集成、流程编排、部署和调试。项目成果经常以一次性代码或个人经验存在，难以在下一次需求中可靠复用。

本平台希望建立统一的组件描述和运行边界，使工程师能够：

1. 将硬件、算法和业务能力登记为可复用组件；
2. 检查组件接口、资源和版本是否兼容；
3. 通过可视化方式组合工作流；
4. 将工作流部署到机器人或边缘计算设备；
5. 观察运行状态，并将验证结果沉淀为方案模板。

## 当前边界

第一阶段只建立控制面与边缘执行端之间的最小通信链路。

包含：

- Web Studio、Platform API 和 Edge Agent 的工程边界；
- Edge Agent 注册；
- Edge Agent 心跳；
- 节点在线状态展示；
- 进程级离线测试。

不包含：

- 真实硬件发现或控制；
- ROS 2、CAN、串口和厂商 SDK；
- 用户系统和权限；
- 数据库存储；
- 工作流画布与执行引擎；
- 云端部署和远程访问；
- 自动硬件或算法选型。

## 可度量验收标准

1. Platform API 的 `/health` 返回服务版本和健康状态；
2. Edge Agent 可以通过 HTTP 注册，Platform API 返回规范化的节点记录；
3. 已注册节点可以发送心跳，未知节点发送心跳时返回 `404`；
4. 超过配置阈值未发送心跳的节点，在查询时显示为离线；
5. Web Studio 能显示 API 连接状态、节点总数和节点列表；
6. Platform API 与 Edge Agent 的自动化测试通过；
7. Web Studio 能完成生产构建；
8. 整个阶段不连接、不启动和不控制真实硬件。

## 开放问题

- 组件协议优先采用平台自定义接口，还是以 ROS 2 接口为主要描述来源；
- 工作流第一版采用数据流、状态机还是行为树作为主要模型；
- Edge Agent 的设备身份如何安全初始化和持久化；
- 本地部署优先提供安装包还是 Docker Compose；
- 组件制品、模型和大型数据集采用何种存储方案。

## 实践意义

这一阶段先验证平台与边缘节点的职责边界。后续所有设备管理、部署和运维能力，都可以沿用同一条受控通信链路扩展，避免让 Web 界面直接访问硬件。

## 下一项具体行动

设计设备描述 `DeviceManifest`，实现一个不依赖真实硬件的模拟设备适配器，并在 Web Studio 中展示 Edge Agent 上报的设备清单。
